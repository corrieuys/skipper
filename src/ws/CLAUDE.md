# src/ws

WebSocket push from server → browser. Used by dashboard polling-replacement + realtime task UI.

**UI update contract (see root [CLAUDE.md](../../CLAUDE.md)):** every state
mutation must emit a domain event so all surfaces reconcile, and a button must
update in place, never full-refresh the view. When you add a task control, add
its event handling here (targeted OOB fragment push, not a full `#mc-main`
refresh, which is guarded on real status transitions only).

Not all of the daemon's sockets live here. `types.ts:WSData` is the shared
upgrade-payload union for every one of them (all registered in `index.ts` via
`setWebSocketUpgradeHandlers` / `setWebSocketHandlers`): `ui-push` and
`realtime` in this dir, `monkey` in [../monkey/CLAUDE.md](../monkey/CLAUDE.md),
and `connect-local` - the inbound local consumer socket `GET /connect/local`
(unauthenticated, loopback only; like every route, the upgrade first passes
`src/server.ts:rejectForeignRequest`, so a foreign `Origin` or a non-local `Host`
gets 403), which lives in
[../connect/CLAUDE.md](../connect/CLAUDE.md) (`local-endpoint.ts`).

| file | use |
|---|---|
| `ui-push.ts` | `UIWebSocketManager` — broadcast fragment refreshes + notifications. Raw JSON notices to HTML clients: `__sk_notify {kind:"audio", sound}` (handled in `skipper.js`) and `{kind:"omarchy", href}` (OS theme switched; `ws-subscribe.js` swaps the `#sk-omarchy-theme` stylesheet link in place, no reload). Dual-format socket: `/ws/ui` (htmx OOB HTML) and `/ws/ui?format=json` (`broadcastJson` envelope `{event, resource, id, data, timestamp}` for machine clients). Both formats honor topic subscriptions. **JSON clients subscribed to `dashboard` (or to nothing) get a one-shot `dashboard:snapshot` on connect** (`buildDashboardSnapshotMessage`: tasks/instances/metrics/phase_indicator/activity) so they hydrate without a REST read — the terminal dashboard (`src/tui`) relies on this; a topic-scoped JSON socket (the glyph overlay on `glyph:<taskId>`, pushed by `src/glyph/engine.ts` as resource `glyph` / `glyph:status`) skips it. `hasJsonClients(topics)` is the public gate out-of-file pushers use before doing expensive work. Live JSON push `dashboard:activity` (parsed output feed incl. notes, debounced on `agent:output` + on `task:note_added`); `dashboard:phase-indicator` already carries `{task}`. **Activity feed is poke-driven:** on `agent:output` the v2 task view gets a tiny OOB `#mc-activity-poke-<taskId>` element (`pushV2ActivityPoke`), never a re-rendered feed; `skipper.js` fetches `/activity?after=<newest row id on screen>` and prepends. **No work for nobody:** JSON-lane pushers call `hasClients` before their query (the 1000-row `pushLogEntries`, `pushDashboardActivity`, every `dashboard:*` / `task:*` lane); `broadcast` / `broadcastRaw` take a render function and skip it when no HTML socket matches; `broadcastJson` returns before serializing. **Push only what a page renders:** the old dashboard and legacy HTML targets (`#active-tasks`, `#dashboard-*`, `#running-instances*`, `#recent-activity`, `#task-list`, `#task-*-fragment`, `#rt-notes`, `#sk-notes`, `#timeline-entries`, `#rt-running-agents`, `#artifact-list`, `#mc-nav-stats-live`, `#mc-task-escalations-*`, `#mc-messages-*`) are gone; their JSON lanes stay for the terminal dashboard (topic `dashboard`) and the VS Code extension (an unscoped JSON socket, so it gets every topic). `tasks` (every task row, every column) goes on topic `tasks-page` only. Agent output chunks and the `agent:streams_drained` whole-session re-render go only to `agent:<instanceId>` (the agent terminal page's `#terminal-lines`). **Every page names its topics** (`v2layout` `wsTopics`): an empty subscription set receives every push, which only unscoped machine clients should have. `recurring:changed` / `team:changed` / `task:created` re-render the command-center sidebar; `instance:state_changed` does too, debounced under one global key and only while an HTML `dashboard` socket is open (rows show the derived working/idle status). `remote_team_repo:changed` (and a `team:changed` for a remote or deleted team) pushes the `/teams` page's `#tm-remote-repos` list OOB (`pushRemoteTeamRepos`, experimental, debounced, topic `teams`, which the teams page subscribes to). `instance:state_changed` re-pushes `dashboard:instances` AND `dashboard:metrics` (`activeAgentCount` follows agent liveness, not only task events). `improvement:changed` patches the Improvements page (topic `improvements`, experimental): a created card goes OOB `afterbegin:#imp-list`, a changed card and its pending siblings on the same target are replaced by id, plus `#imp-pending-count`; `team:changed` / `recurring:changed` also re-render that team's / series' pending cards, since their conflict state follows the live text (`pushImprovement` / `pushScopedImprovements`). The top-bar attention indicator `#sk-attention` (experimental) is pushed OOB on topic `attention` (`pushAttention`, debounced) on `improvement:changed`, `escalation:created|resolved`, `task:needs_review_changed`, `task:state_changed`, `task:run_completed|failed`; `shell/layout.ts:v2layout` appends `attention` to every page that names topics. |
| `dashboard-activity.ts` | `buildDashboardActivity` — recent agent stdout parsed to `{agent, kind:message\|tool\|event, text}` via `summarizeTerminalLine` (the pure classify+summarize step in `src/html/terminalJsonSummary.ts`, shared with the TUI's per-task output tail), **merged with `task_notes` as `kind:"note"`** (interleaved by time), JSON-shaped for the TUI output feed. Web feed's classify logic minus HTML; drops noise (rate_limit / system-hook / unparseable) instead of dumping raw JSON |
| `fragment-registry.ts` | Map fragment keys → render fn for diff push. `topicMatches` routes every push (exact or `prefix:*` wildcard; an empty subscription set gets every topic) |
| `types.ts` | Shared event payload types |
