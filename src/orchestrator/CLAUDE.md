# src/orchestrator

Modules called by `agents/manager-daemon.ts` facade in response to bus events.

| file | use |
|---|---|
| `tick-loop.ts` | 30s reconciliation. Health check, stale recovery, queue process, delegation/escalation cleanup, checkpoint persist, log retention. Hourly `autoDeleteOldTasks` sweep deletes `settled` tasks past a configured age (`settled_at`, fallback `updated_at`), with separate day-windows for one-off vs recurring-run tasks (`app_settings.task_retention_days` / `recurring_task_retention_days`, 0 = off); deletes via `TaskScheduler.deleteTask` for the full cascade. 5-min `rotateOversizedLogFile` caps the daemon's stdout/stderr `skipper.log` (snapshot → `.old` + in-place truncate; `SKIPPER_LOG_MAX_BYTES`, default 25 MB) — only when fd 1 is that file, so dev runs are untouched |
| `task-runner.ts` | Queue: pull next startable task (`getNextStartableTask`) under the concurrency cap (slot = active task with live agents or paused; 5 with parallel execution on, else 1; `hasFreeTaskSlot(db)` is exported so the idle poke obeys the same cap). First start spawns the entrypoint with prompt + phase context; a wake appends the pending INPUT_FEED block (from the input pipeline's `consumePendingFeed`) to the full resume/cold prompt via `joinPromptKeepingTail`: over the 100KB limit the base is cut from its end and the feed goes out whole, and the base's notes are then not recorded as delivered. A feed block over the limit on its own is appended as before (cut at delivery, all entries marked fed): `consumePendingFeed` has one commit for all entries, and unfed entries would be redelivered every run. Teamless conversational tasks feed via the pipeline (`TaskWakeFeeder.feedTask`). A start that fails before the prompt is delivered (no team entrypoint, entrypoint agent gone, spawn throws, prompt write throws) calls `failRun(..., { startFailed: true })`: the task settles as Failed even with input waiting, because a keep-active wake would re-enter the same failing start in an endless loop. The input stays unfed and the next revive delivers it with any new input |
| `phase-manager.ts` | `[PHASE_COMPLETE]` + `[PHASE_REGRESSION]` handling. Regression respawn + dedup guards. `handlePhaseRegression` returns a `PhaseRegressionOutcome` (`regressed` / `denied_max_regressions` / `noop_invalid_target` / `noop_not_running` / `noop_unresolved`). Agent regressions and operator review rejects clear the dedup keys of every phase from the target through the old current phase |
| `delegation-manager.ts` | Delegation signals. Spawn child instance/batch. Track groups. Resume parent on complete. Timeout 60min. **Delegated children may delegate onward** — `delegate`/`delegate_batch`/`delegate_resume` are gated only by `!isSolo` (`mcp/tools.ts`), not by `isDelegated`, so nesting is allowed. No numeric depth / per-parent / batch-size cap is enforced (`getDelegationDepth()` exists but is currently uncalled). Nesting is bounded structurally instead: no self-delegation; a non-entrypoint cannot delegate to the entrypoint; **cycle guard** `isAncestorTemplateInActiveChain` blocks delegating to a template already an ancestor in the active pending/running chain; **one active delegation group per parent** at a time; target must be in the same team (or the task's assigned-agent set); parent must support stdin or resume. Optional per-delegation working directory (`delegate`'s `working_directory` → `delegations.working_directory`): sets the child's `WORKING DIRECTORY:` prompt line **and** its spawn cwd — the only case where a child does not start in the orchestrator's cwd. `validateWorkingDirectory()` (exported here) requires an absolute path that exists; a retry/resume replays the stored value. **Resume drains the pending input feed:** `routeResultToParent` (parent resume on delegation complete) enriches the result payload with unseen notes AND, via the injected `TaskWakeFeeder` (`setWakeFeeder`, the same `RealtimeSessionManager`), any operator input that arrived while the delegation was open (`consumePendingFeed`) — committed (`fed_to_skipper=1`) only on a delivery path that actually reaches the parent (running-parent `sendInput`, or successful async resume); a failed/orphaned resume leaves the feed unfed so the next run redelivers it. Without this, mid-delegation input stayed "queued for agent" until a whole new run started, and the resuming parent could conclude on stale context. **Escalation hold:** while an escalation is open on the task, a group whose last member settles stays `running` with `settled_count = expected_count` and nothing reaches the parent. `releaseHeldDelegationGroups` delivers it once: when the last escalation closes, at the parent's own exit if it was running, or on the stale sweep. A group is stale only when no unsettled member has an attempt younger than 60 min; held groups and tasks with an open escalation are skipped. A **dismissed** escalation resumes nothing, so `failDelegationForDismissedEscalation` (called from the daemon's `escalation:resolved` handler on `dismissed: true`) fails the delegation of the halted child that raised it with "Escalation dismissed by operator" and runs the normal group progress; a child that is still running is left for its own exit. A retry whose spawn returns false settles as failed while still pending |
| `recovery-manager.ts` | Startup cleanup, stale-task recovery (WORKFLOW mode only; conversational tasks rest idle and re-feed on input; skips tasks marked idle-at-rest by a clean root exit — the `idle_since:` daemon_state key — which belong to idle-poke-manager, so a deliberate stop is nudged/escalated instead of crash-recovered), checkpoint R/W, orchestration state persist, one-shot recovery safeguard (exhaustion now `failRun` + step IDLE, task stays active; new input resumes). `cleanupTerminalTaskState` (the daemon's handler for `task:state_changed` to settled) stops every in-memory runtime of the task with `killAgentTree`, the root included (on a `completeRun` settle, the root that called `complete_task`): the settle already moved the instance rows to completed/failed, so only the runtime map still shows what is alive. A killed runtime's exit then finds the task settled and `handleAgentExit` bails |
| `health-monitor.ts` | Liveness, orphan detect, stuck diag (below), clustered-exit escalate. Reaps use `updateInstanceStatus`, which emits `instance:state_changed`, so rosters (web, TUI, apps) drop the ghost at once. `runStuckDetection` (60 s timer) drives `agents/state-tracker.ts` per runtime instance: a runtime whose own output stays unchanged is nudged after 10 min and again every 10 min up to 3 nudges, then escalated on its own task and killed 10 min after the third; other runtimes of the same template (other tasks' roots) are judged on their own rows |
| `artifact-manager.ts` | Versioned immutable artifacts. CRUD called from MCP tools (`create_artifact`/`get_artifact`/`list_artifacts`). Bodies carry a `format` (`html`\|`markdown`); `createArtifact` resolves it (explicit, else `looksLikeHtml` inference) and, when it resolves to `html`, runs `html-validator.ts` inline — a failed validation throws `ArtifactHtmlValidationError` (line/col/tag) and nothing is persisted. Per-version publish state (`publishArtifact`/`unpublishArtifact`/`getPublishedArtifact`) for public links via connect. **File artifacts** (operator uploads, `kind='upload'`, `storage='file'`): `createFileArtifact` validates (25 MB cap `MAX_FILE_ARTIFACT_BYTES`; a declared `image/*` must sniff as PNG/JPEG/WebP/GIF via `image-meta.ts`, whose mime + dimensions then win; other mimes are taken as declared, fallback `application/octet-stream`), computes sha256, writes the bytes ONCE to `<data dir>/artifacts/<taskId>/<id>.<ext>` (`artifact-files.ts`; constructor option `artifactsRoot` overrides for tests), inserts the row with `body` = caption (empty string when none), emits `artifact:created`. `getArtifactFilePath` / `readArtifactBytes` (null for inline). `artifactToJson` is the HTTP projection (file rows: no body, `description` + `file_url`). Chunked upload sessions for connect: `beginUpload` (size/mime/sha256 checks) → `appendChunk` (sequential index, declared-size guard) → `commitUpload` (size + sha256 verify, then `createFileArtifact`) / `abortUpload`; in-memory, 2 min idle expiry (`UPLOAD_SESSION_TTL_MS`) |
| `artifact-files.ts` | On-disk layout helpers for file artifacts: `getArtifactsRoot()` (`<data dir>/artifacts`), `taskArtifactDir`, `removeTaskArtifactFiles(taskId)` (called by `TaskScheduler.deleteTask`), `sanitizeArtifactFileName` (the versioning key is the sanitised original filename, so a re-upload of the same name becomes the next version), `fileExtensionFor`, `mimeFromExtension` (small extension→mime map for the `create_file_artifact` tool: images, pdf, txt, md, csv, json, zip, mp4, mov, wav, mp3, log, html; null otherwise), `formatBytes` |
| `image-meta.ts` | `detectImage(bytes)`: dependency-free magic-byte sniff + header dimension parse for PNG/JPEG/WebP/GIF. `image-fixtures.ts` builds minimal header-only fixtures for tests |
| `html-validator.ts` | `validateArtifactHtml(body)` — dependency-free tag-stack parser that rejects malformed artifact HTML (mismatched/unclosed tags, disallowed `script`/`style`/`iframe`/document-wrapper tags) with the line/column where the node tree broke. Bun's `HTMLRewriter` is too lenient to catch these. Called by `artifact-manager.ts` at create time |
| `realtime-session.ts` | Universal input pipeline (every task): recording lock + cadence audio ingest, transcribe, summarize, timeline entries. With a NeMo streaming model running, a recording's chunks go through one live speech stream (`streamPendingSegments`, see [../speech/CLAUDE.md](../speech/CLAUDE.md)) instead of one HTTP transcription per chunk. Text ingest is sessionless (any active task). Feeds route through `TaskScheduler.requestWake` → queue → task-runner (cap-respecting); implements task-runner's `TaskWakeFeeder`. `prepareTaskForInput(taskId)` is the shared admission step for any input (settled → `reviveTask`, open review gate → cleared; returns `draft`/`active`), used by `ManagerDaemon.inputTask` and by `ingestArtifactUpload(taskId, artifact, {caption?, source})`, which inserts an `image`/`file` `realtime_timeline` row (`content` = caption else filename, `artifact_id`, priority high, unfed), emits `realtime:timeline_updated` + `realtime:window_ready`, then applies the same wake semantics as text (draft = stored, consumed by the first run's `consumePendingFeed`; active → `requestWake`, busy roots accumulate). Both feed formatters (`consumePendingFeed` and `feedSkipper`) go through `formatFeedLine`: upload entries render as `[HH:MM:SS IMAGE PRIORITY:HIGH] Operator attached an image artifact "name" (v2, 2048x1536): <abs path> - caption: "...". View it with your file/image reading tool before you continue.` (files: `(v1, application/pdf, 1.2 MB)` + `Read it with your file-reading tool...`); the bytes never travel through the prompt. `ingestAgentArtifact(taskId, artifact, {agentId})` is the agent-output counterpart (the `create_file_artifact` MCP tool): inserts the `image`/`file` row with `fed_to_skipper = 1`, priority `normal`, emits only `realtime:timeline_updated`; no status change, no wake, no `realtime:window_ready`, and the feed queries skip it |
| `idle-poke-manager.ts` | Nudge stuck agents that go silent (workflow-mode tasks only; settled runs at step IDLE rest). The live-root check is scoped to the task (`getRunningInstanceForTask`). A poke spawns the root outside the queue, so it waits for a free concurrency slot (`task-runner.ts:hasFreeTaskSlot`, the queue's own cap check): with none free the task stays idle and is poked on a later tick, poke count unchanged. After two no-op pokes it raises an `idle_poke_exhausted` escalation through `EscalationManager.createEscalation`, which emits `escalation:created` |
| `state.ts` | `TaskOrchStep` state machine. Transition validate + log |
| `phase-config.ts` | `resolvePhaseConfig()` — merge team base phase + per-task `task_config.phase_overrides` (prompt + review gate) |
| `types.ts` | `OrchestrationState`, `TaskCheckpoint`, regression metadata |

## Phase advancement

Non-streaming agents advance on exit code 0 via `handleSuccessfulExit`. Active delegation blocks completion — check `getActiveDelegationForParent` first.
