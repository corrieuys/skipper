# src/tasks

Task CRUD + state machine.

| file | use |
|---|---|
| `scheduler.ts` | Task CRUD + unified state machine: `draft/active/settled` stored; runtime substate derived (`getRuntimeState`). `approveTask` (draft→active, queues first start via `wake_requested_at`), `unapproveTask` (only before first start), `markStarted`, `requestWake`, `completeRun`/`failRun` (run settles the task to stored `settled`, presented as Completed/Failed; emit `task:run_completed`/`task:run_failed`; input revives via `daemon.inputTask` → `reviveTask`+wake), `settleTask` (cancel path), `reviveTask`, `setAutopilot` (flips mode workflow/conversational; drives the DRIVE MODE prompt block + poke/recovery gating), `pauseTask`/`resumeFromPause` (paused flag), `getNextStartableTask` (queue pull: active, unpaused, no review, wake pending or never started, no live instances). Iterate/retry/resume are GONE — new input via `daemon.inputTask` wakes an idle task instead (see root CLAUDE.md Task lifecycle). `addExternalNote(taskId, content, source)` records a note authored outside the agent runtime (e.g. a human reply in the origin Slack thread — see [../slack/CLAUDE.md](../slack/CLAUDE.md)), attributed to the team entrypoint agent for the FK. **Icon + star:** `setStarred(id, on)` toggles the stored `starred` flag (sidebar Favorites board) and `setIcon(id, icon, color)` sets the Lucide `icon`/`icon_color`; both emit a same-status `task:state_changed` (like `updateTitle`). `createTask`/`updateTask` accept `icon`/`iconColor` (sanitized at the route layer via `html/atoms/lucide:sanitizeIcon` + `creature:sanitizeColor`). `Task` carries `starred`/`icon`/`icon_color` |
| `status.ts` | Presentation layer: `deriveDisplayStatus(db,row)` → draft/queued/working/idle/paused/review/blocked/completed/failed (stored `settled` splits on result.error; pass `result` in the row), `displayStatusLabel`, `resultHasError`. No legacy status mapping: every surface (web, Connect v3, mobile) reads the unified status plus `display_status` |
| `title-generator.ts` | `generateTaskTitle(db,{description,runInput})` asks the operator-configured **Task Title Generator** agent (config page, `model-settings.ts` `getTaskTitleModelOverride` / `isTaskTitleGeneratorConfigured`) for a short title via `agents/oneshot.ts:runOneShotText` (tool-less, claude isolation); returns null if unconfigured/failed. `ensureTaskTitle(db,scheduler,taskId,{runInput?,force?})` (fire-and-forget, called right after create when the title is blank) generates and persists via `scheduler.updateTitle`, falling back to a timestamp ONLY when a configured generator's call fails. A blank title is accepted at create time **only when a generator is configured** (else the create routes still reject it); `updateTitle` emits a same-status `task:state_changed` so the web UI + Connect (`serializers.ts:projectTask` carries `title`) get the new title within ~1-2s. |
| `scheduled-scheduler.ts` | Scheduled task firing → creates task. Two mutually exclusive schedule modes: fixed interval (`schedule_unit`/`schedule_amount`) or weekly matrix (`schedule_matrix`, JSON 7x24 of 0/1, local time, fires at top of enabled hour via `calculateNextRunFromMatrix`). Cron firing (`manager-daemon.ts:fireStandardScheduledTask`) is **singleton per scheduled task**: it skips a new run while a prior run is still `active` (runs auto-settle, freeing the slot) and still advances `next_run_at` past the skipped slot, so a sleep/wake catch-up burst of overdue slots can't spin up overlapping runs of the same recurring task. Manual "Run Now" (`runTaskNow`) is intentionally not guarded. `findScheduledTaskBySlashCommand` matches a Slack slash command bound via `task_config.slashCommand` (runs the task now via Socket Mode - see [../slack/CLAUDE.md](../slack/CLAUDE.md)). `runTaskNow(id, taskScheduler, runInput?, { slackOrigin? })` stamps the optional per-run input (`tasks.run_input`, injected into the run prompt) and, for Slack-triggered runs, `task_config.slack_origin` (so the run can reply to Slack). `global_store_instructions`: free-text global-store contract merged into every spawned run's `task_config` and injected into the root prompt by `prompt-builder.ts`. Recurring tasks also carry `starred`/`icon`/`icon_color` (create/update accept `icon`/`iconColor`; `setStarred`/`setIcon` toggle them) — a starred recurring task shows in the sidebar Favorites board. Webhook trigger lifecycle (`enableWebhook`/`regenerateWebhookKey`/`disableWebhook` on `webhook_key`; `setWebhookDebounce` leading-edge debounce in minutes, floor 1, enforced by `runWebhookTask` - ignored webhooks restamp the window) - public trigger URL relayed via connect, validated in `connect/resources.ts` |

Lifecycle states + transitions documented in root [CLAUDE.md](../../CLAUDE.md).

`TaskScheduler.deleteTask` also sweeps the task's file-artifact folder (`<data dir>/artifacts/<taskId>`, see `orchestrator/artifact-files.ts`) after the row cascade, since uploaded bytes live outside the DB.
